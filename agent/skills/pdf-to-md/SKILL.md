# PDF to Markdown Conversion with Visual Formula Error Correction

Converting scientific and academic PDFs (especially those generated by WPS or Microsoft Word) to Markdown is notorious for fundamental failures:
1. **Mathematical Formula Corruption**: MathType and equation editors embed symbols using **Private Use Area (PUA) unicode glyphs** (`\uf0ce`, `\uf03d`, `\uf0e5`, `\uf0ea`, `\uf0e9`, `\uf065`, `\uf070`) from embedded fonts (`Symbol`, `MT Extra`, `Wingdings`). Plain text extractors extract these as garbled unicode or missing characters.
2. **Fractured 2D Layout & Sentence Linebreaks**: Fractions, summations, and matrices are broken into disjointed vertical text tokens (`l w\nLB\nL W\n\uf0ce...`), while prose paragraphs suffer from mid-sentence hard line-breaks.
3. **Dirty HTML Tags & Absolute Paths**: Naive converters inject `<p align="center"><b>...</b></p>` and absolute system file paths (`/home/user/...`), breaking portable Markdown rendering.
4. **Vector Diagrams & Multi-Image Loss**: Flowcharts drawn with vector paths are dropped by standard raster image extractors, and multi-figure pages often collapse to the first image.

This skill provides an **automated layout-reconstruction engine + Visual Formula Grounding Pipeline** that produces **pure standard Markdown** (zero HTML tags, relative image paths, smooth paragraph prose, standard LaTeX formulas, GFM tables, and syntax-highlighted code blocks).

## 3. PDF Layout & Semantic Reconstruction Rules

### 3.1 Pure Standard Markdown (Strictly Zero HTML)
Do **not** output HTML tags like `<p align="center">`, `<b>`, `</b>`, or `</p>`. Use standard Markdown formatting:
- Image with caption:
  ```markdown
  ![Caption](figures/fig_1.png)

  **Caption**
  ```
- Table caption:
  ```markdown
  **Table 1 Caption**
  ```

### 3.2 Relative Image Paths & Geometric Proximity Matching
- All extracted images are referenced using **relative file paths** from the generated Markdown file (`![Caption](figures/fig_1.png)`).
- On pages with multiple figures, captions are geometrically matched to the raster image immediately above them.
- If a figure is drawn using vector paths, the system automatically falls back to high-res bounding box pixmap capture.

### 3.3 Continuous Paragraph Prose Unwrapping & De-Hyphenation
- Mid-sentence hard line-breaks (`\n`) are unwrapped into continuous, smooth sentences while preserving paragraph breaks (`\n\n`).
- Soft hyphen line-breaks (e.g., `optimi-\nzation`) are automatically repaired into clean unified words (`optimization`).

### 3.4 Defensive Heading Candidate Guard
A text block is only elevated to a Markdown heading (`#`, `##`, `###`, `####`) if:
1. Character length $\le 50$.
2. Does NOT end with sentence-ending punctuation (`。`, `！`, `？`, `：`, `:`, `；`, `;`).
3. Does NOT end with transition phrases (`如下`, `所示`, `如下表`, `如下图`).

### 3.5 Pre-Formula Explanatory Text Separation
When an equation tag is detected in a text block, pre-formula introductory prose (e.g., `由几何关系可得闭式解如下：`) is cleanly split and preserved as preceding Markdown text rather than being obliterated by the display formula block.

### 3.6 GFM Table Sanitizer
Data tables are reformatted into clean GFM pipe syntax with alignment colons (`:---` for column 1, `:---:` for others). Completely empty rows and unfinished draft rows are automatically discarded.
