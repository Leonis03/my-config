# 零基础小白也能懂的 Docker 指南：把软件打包进“魔法集装箱”

---

## 一、什么是 Docker？

如果你问一个程序员：“为什么要用 Docker？”  
他大概率会告诉你一句话：**“为了解决‘在我的电脑上明明能跑，在你的电脑上怎么就报错了’的问题。”**

### 通俗比喻：搬家与“太空胶囊舱”

* **传统装软件（像传统搬家）**：  
  你想在新电脑上玩一个软件或跑一段 AI 代码，需要自己去装系统、装各种 Python 版本、配置环境变量、装驱动……只要其中一个版本对不上，软件就直接崩溃。就像搬家时把床、沙发、管道零件一件件散装运过去，到了新家还得重新组装，经常发现螺丝尺寸不对。

* **使用 Docker（像空投预装好的“胶囊公寓”）**：  
  软件开发者不仅把软件本身打包，连同软件运行所需要的所有**系统环境、依赖库、配置文件**全部装进一个密封的“标准化集装箱（容器）”里。  
  **不管在谁的电脑上，只要装了 Docker，把这个集装箱拿过来一键点火，它就能在里面完美运行，外界环境完全无法干扰它。**

```
┌──────────────────────────────────────────────────────────┐
│                      你的物理电脑 / WSL                  │
│                                                          │
│   ┌─────────────────────┐      ┌─────────────────────┐   │
│   │   集装箱 A (Python)  │      │   集装箱 B (NodeJS) │   │
│   │ ┌─────────────────┐ │      │ ┌─────────────────┐ │   │
│   │ │ 独立文件系统    │ │      │ │ 独立文件系统    │ │   │
│   │ │ 自己的软件环境  │ │      │ │ 自己的软件环境  │ │   │
│   │ └─────────────────┘ │      │ └─────────────────┘ │   │
│   └─────────────────────┘      └─────────────────────┘   │
└──────────────────────────────────────────────────────────┘
```

## 二、3 分钟搞懂 Docker 三大核心概念

| 概念     | 英文名                    | 生活比喻                         | 作用                                                         |
| :------- | :------------------------ | :------------------------------- | :----------------------------------------------------------- |
| **镜像** | **Image**                 | **预制菜 / 乐高图纸 / 安装光盘** | 静态的模板文件，**只读不可修改**。里面包含了运行某个软件所需的一切。 |
| **容器** | **Container**             | **加热好的快餐盒 / 盖好的房子**  | 镜像运行起来后的**动态实体**。你可以进入它、在里面写代码、删除它。 |
| **仓库** | **Registry / Docker Hub** | **手机应用商店 / 外卖超市**      | 全球开发者存放、分享做好的镜像的地方，随时可以一键下载（`pull`）。 |

> **一句话关系**：  
> 你从**应用商店（仓库）**下载了一张**光盘（镜像）**，放入电脑后运行出了一个**独立游戏世界（容器）**。

## 三、为什么 AI 时代特别需要 Docker？（防爆实验室）

让 AI Agent（例如自主执行代码的智能助手）在电脑里自由跑命令时，大家最担心的是它“乱删文件”或“把电脑环境搞坏”。

* **防爆安全隔离**：容器就像一间**全封闭的防爆实验室**。
* **随时还原**：就算 AI Agent 在容器内部执行了极度危险的 `sudo rm -rf /*`（强制删除全部文件），**损坏的也仅仅是这间临时实验室本身**。
* **物理机毫发无损**：你的 WSL 宿主机系统、Windows 系统文件、照片文档完全不受影响。你只需要敲一行命令删掉这个坏容器，再花 1 秒钟新建一个，一切立即满血复活！

## 四、在本机如何启用与使用 Docker？

在本机（WSL Ubuntu）上，**Docker 已经全部安装、配置妥当，并且已作为后台服务自动开机运行，随时可以直接使用！**

打开终端，你可以通过以下几个最常用的场景快速上手：

### 场景 1：进入一个“随便搞破坏也不怕”的临时隔离沙盒

```bash
# 启动一个临时的 Ubuntu 容器并进入交互终端（--rm 表示退出时自动销毁，不留垃圾）
docker run -it --rm ubuntu:26.04 bash
```
> 💡 进入后，终端提示符会变成类似 `root@a1b2c3d4e5f6:/#`。此时你就像进入了一个全新的纯净 Ubuntu 系统。你可以随意测试各种命令，哪怕执行了误删操作，只要输入 `exit` 退出，所有破坏都会随之消失。

---

### 场景 2：给 AI Agent 划定一个“专属工作文件夹”

如果你想让 AI Agent 处理你电脑里的某个项目文件，又不想让它碰到其他私密文件，可以通过 `-v` 参数（目录挂载）把**指定的独立文件夹**映射进容器：

```bash
# 1. 在本地创建一个安全的沙盒文件夹
mkdir -p $HOME/code/docker/sandbox

# 2. 启动容器，并仅将该文件夹挂载到容器的 /app 目录下
docker run -it -v $HOME/code/docker/sandbox:/app ubuntu:26.04 bash
```
* **效果**：容器内部只能看到和修改 `/app` 里的文件，电脑里其他磁盘、用户个人主目录对容器来说统统是“不可见、碰不到”的。

---

### 场景 3：一键运行各种现成服务（例如 Python、Web 服务器）

* **运行一个纯净的 Python 环境**：
  ```bash
  docker run -it --rm python:3.12-slim python
  ```
* **在后台运行一个轻量级 Web 网页服务器（Nginx）**：
  ```bash
  docker run -d -p 8080:80 --name my-web nginx
  ```
  *(启动后在 Windows 浏览器输入 `http://localhost:8080` 就能看到网页)*

## 五、Docker 日常高频操作速查表

| 你想做什么                       | 终端命令                   | 说明                           |
| :------------------------------- | :------------------------- | :----------------------------- |
| **查看当前正在运行的容器**       | `docker ps`                | 看看有哪些“胶囊舱”在开机运行   |
| **查看所有容器（包括已停止的）** | `docker ps -a`             | 列出全部历史容器记录           |
| **查看本地保存的所有镜像**       | `docker images`            | 查看电脑里存了哪些“预制菜”     |
| **停止某个运行中的容器**         | `docker stop <容器名或ID>` | 相当于安全关机                 |
| **删除已经停止的容器**           | `docker rm <容器名或ID>`   | 清理垃圾，释放空间             |
| **删除不需要的镜像**             | `docker rmi <镜像名>`      | 删掉不再使用的安装模板         |
| **一键清理所有无用的临时垃圾**   | `docker system prune -f`   | 释放被废弃容器和缓存占用的磁盘 |

## 六、新手核心注意事项

1. **认准命令执行位置**：
   * 只有在终端前面带有 `docker run`、`docker exec` 时，命令才是在隔离的“集装箱”里跑。
   * 如果直接在 WSL 宿主终端敲命令，那是直接作用在你的宿主机系统上的。
2. **谨慎挂载宿主机敏感目录**：
   * 永远不要把宿主机的根目录 `/` 或 Windows 盘符 `/mnt/c` 直接挂载给不可信的脚本/Agent（即避免使用 `-v /:/host` 或 `-v /mnt/c:/c`）。
   * 遵循**“需要哪个文件夹，就只挂载哪个文件夹”**的最小权限原则。
